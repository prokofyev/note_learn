## Context

См. `proposal.md` — Why. Текущее состояние, важное для решения:

- `note_learn/app.py`: окно создаётся жёстко — `self.width, self.height = 1180, 760`, затем `pygame.display.set_mode((self.width, self.height), flags)`, где `flags = pygame.HIDDEN if headless else 0`. Все экраны верстаются абсолютными координатами внутри полотна 1180×760 (например, `_draw_users_screen` использует `pygame.Rect(760, 136, 380, 470)`).
- Обработка клавиш — `_handle_keydown`; `Esc` уже занят (выход на карту курса / выход из приложения), поэтому переключение режима экрана вешаем на свободную `F11`.
- `note_learn/renderer.py`: ассеты альтерации загружаются в `_load_accidental_assets()` через `pygame.image.load` + `convert_alpha()` (если есть display surface) и кэшируются по высоте в `get_accidental_surface()` с `pygame.transform.smoothscale`. Скрипичный ключ рисуется векторно в `_draw_treble_clef(surface, cx, bottom_line_y, line_spacing)` вызовами `pygame.draw.arc`/`line`/`circle`.
- `assets/GClef.png` уже добавлен: 500×1343, 32-бит с альфа-каналом (пропорция высота:ширина ≈ 2.69).
- Проверено на реальном драйвере (`cocoa`, дисплей 1792×1120): `set_mode((1180, 760), pygame.FULLSCREEN | pygame.SCALED)` возвращает поверхность 1180×760 и физическое окно 1792×1120, то есть вёрстка масштабируется без изменения координат. Переключение `SCALED` ↔ `FULLSCREEN|SCALED` работает без перезапуска.
- Существующие спеки: `gamified-ui`, `music-theory-and-staff`, `adaptive-curriculum`, `audio-and-microphone`, `user-profiles`.

## Goals / Non-Goals

**Goals:**
- Полноэкранный запуск с сохранением координатной вёрстки 1180×760 (без переписывания экранов на относительные координаты).
- Переключение `F11` между полноэкранным и оконным режимом без перезапуска.
- Отказоустойчивый откат в оконный режим и сохранение headless-режима для тестов.
- Скрипичный ключ из `assets/GClef.png` с сохранением пропорций и выравниванием по линейке «Соль», с векторным запасным вариантом.

**Non-Goals:**
- Адаптивная переверстка интерфейса под произвольное соотношение сторон (вёрстка остаётся 4:3-ish 1180×760 и масштабируется целиком).
- Поддержка смены разрешения/монитора на лету, Drag&Drop, настройки пользователя «запомнить оконный режим».
- Изменение самих нот, аппликатур, аудио или логики курса.

## Decisions

### 1. Полноэкранный режим через `FULLSCREEN | SCALED`, вёрстка остаётся 1180×760
- **Решение**: в обычном режиме создавать окно как `pygame.display.set_mode((1180, 760), pygame.FULLSCREEN | pygame.SCALED)`; `SCALED` отвечает за масштабирование логического полотна 1180×760 на физический экран (в том числе с учётом Retina), поэтому все существующие абсолютные координаты экранов продолжают работать без изменений.
- **Почему**: сохранение координат даёт минимальный диф и отсутствие риска поехавшей вёрстки; `SCALED` снимает проблему разных разрешений и DPI — проверено, что поверхность остаётся 1180×760 при физическом 1792×1120.
- **Альтернативы**: пересчитывать координаты каждого экрана относительно `screen.get_size()` — большой объём правок и высокий риск регрессий; `pygame.display.set_mode((0,0), FULLSCREEN)` — меняет координатную систему под разрешение экрана, ломает вёрстку; `pygame.SCALED` без `FULLSCREEN` — окно вместо полного экрана, не выполняет требование.

### 2. Флаг конструктора `fullscreen` и метод `set_fullscreen()`
- **Решение**: добавить в `TrumpetLearningApp.__init__` параметр `fullscreen: bool = True`; при `headless=True` полноэкранный режим игнорируется (используется `HIDDEN`, как сейчас). Переключение выполняется методом `set_fullscreen(enabled)`, который вызывает `pygame.display.set_mode(...)` с нужными флагами; повторное пересоздание поверхности безопасно, так как display уже инициализирован.
- **Почему**: тесты (`tests/test_app.py`) создают приложение с `headless=True` и не должны требовать дисплея; явный параметр позволяет тестировать оконный и полноэкранный режимы по отдельности.
- **Альтернативы**: читать режим из переменной окружения — неявно и хуже тестируется; всегда полноэкранно — ломает headless-тесты и запуск в CI.

### 3. Отказоустойчивость: `try/except` вокруг установки полноэкранного режима
- **Решение**: установку `FULLSCREEN | SCALED` обернуть в `try/except pg.error` (и общий `Exception`), при неудаче — откатиться на оконный `set_mode((1180,760), 0)`; если и это не удалось в headless — использовать `HIDDEN`.
- **Почему**: требование «не падать при недоступном полном экране»; среда без дисплея и экзотические драйверы не должны ронять приложение.
- **Альтернативы**: полагаться на то, что SDL сам откатится — не гарантируется и не даёт контролируемого поведения.

### 4. Переключение режима по `F11`
- **Решение**: в `_handle_keydown` до проверок экранов обработать `pygame.K_F11` вызовом `set_fullscreen(not self.fullscreen)`; клавиша не конфликтует с существующими (`Esc`, `Enter`, `Space`, `J/K/L`, `1..4`, `H`, `0`).
- **Почему**: `F11` — привычный стандарт переключения полного экрана; `Esc` уже занят навигацией, менять его смысл — регрессия.
- **Альтернативы**: кнопка в интерфейсе — дублирует горячую клавишу и добавляет вёрстку в тесную верхнюю панель; `Alt+Enter` — менее очевидно для ребёнка.

### 5. Ключ из `assets/GClef.png` с кэшем масштабирования и векторным fallback
- **Решение**: в `UIRenderer` добавить `_load_clef_asset()` (по образцу `_load_accidental_assets`, с `convert_alpha()` при наличии display) и `get_clef_surface(target_height)` с кэшем `pygame.transform.smoothscale`, сохраняющим пропорции; в `draw_staff_card` вместо прямого `_draw_treble_clef` сначала пробовать ассет, а при его отсутствии — вызывать прежний векторный метод. Выравнивание: центр ключа совмещается со второй линейкой «Соль», высота задаётся кратной `line_spacing`.
- **Почему**: переиспользует уже существующий в проекте паттерн загрузки/масштабирования PNG (знаки альтерации), даёт единый вид и оставляет надёжный fallback, что и требует спека.
- **Альтернативы**: перерисовать ключ векторно «красивее» — не использует имеющийся ассет и не выполняет пожелание; встроить PNG в код base64 — лишняя сложность без выгоды.

## Risks / Trade-offs

- [`SCALED` сглаживает картинку на нецелых масштабах] → Для 1180×760 на типичных экранах масштаб близок к целому; при необходимости можно добавить `pygame.SCALED` + `vsync=1`. Визуально проверено, что текст и стан читаемы.
- [Переключение режима может терять фокус/пересоздавать поверхность] → После `set_mode` продолжаем рисовать на `self.screen`, который переприсваивается; тесты проверяют, что `draw()` не падает после переключения.
- [PNG ключа может не совпасть по пропорциям с прежним векторным] → Масштабирование с сохранением пропорций и выравнивание по линейке «Соль»; при сильном отличии высота подбирается кратной `line_spacing` (примерно 4.6–5.0 `line_spacing`).
- [В среде без дисплея полноэкранный режим недоступен] → Откат в оконный, а в headless — `HIDDEN`; покрыто тестом.
- [Ассет отсутствует/повреждён] → Векторный fallback; тест подменяет `assets_dir` на каталог без `GClef.png`.
