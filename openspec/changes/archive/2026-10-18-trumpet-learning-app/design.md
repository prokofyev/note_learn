## Context

См. `proposal.md` для описания мотивации и набора возможностей.
В репозитории уже присутствуют:
- Python `>=3.13` (`pyproject.toml`, `main.py`).
- Графические ассеты знаков альтерации: `assets/accidental_sharp.png`, `assets/accidental_flat.png`, `assets/accidental_natural.png`.
- Аудио-сэмплы трубы: `assets/trumpet/trumpet_60.ogg` .. `trumpet_84.ogg` (моно, 22050 Гц, длительность ~1.2 с), где номер файла соответствует MIDI-ноте в концертном строе C (например, `trumpet_60.ogg` имеет частоту ~261.6 Гц).
Так как целевой инструмент ученика — стандартная труба в строе Си-бемоль (B♭), написанная нота `M` (written MIDI) звучит на трубе как `M - 2` полутона (concert MIDI).

## Goals / Non-Goals

**Goals:**
- Обеспечить точное совпадение звучания сэмплов приложения с реальной трубой Си-бемоль (-2 полутона).
- Реализовать отзывчивый графический интерфейс (60 FPS) с плавными анимациями нотного стана, трёх помп трубы, частиц и тюнера без внешних игровых движков.
- Обеспечить надёжное определение высоты звука и длительности с микрофона в реальном времени без сложных платформозависимых C-расширений.
- Построить модульную архитектуру, где музыкальная модель, адаптивный курс (Spaced Repetition) и детектор частоты покрыты автотестами.

**Non-Goals:**
- Многоголосное распознавание (труба — монофонический инструмент).
- Сетевая синхронизация или облачные профили (достаточно локального JSON-файла прогресса).
- Сложная вёрстка партитур из нескольких страниц (фокус на интерактивных карточках, отдельных нотах разной длительности и коротких фразах).

## Decisions

### 1. Графический и аудио-фреймворк: `pygame-ce`
- **Решение**: Использовать `pygame-ce` (Community Edition).
- **Почему**: Отличная совместимость с Python 3.13 и macOS, встроенная поддержка `.ogg` через `pygame.mixer`, быстрая 2D-графика с поддержкой альфа-каналов (`SRCALPHA`) для плавной отрисовки нотного стана, масштабирования PNG-знаков альтерации, пружинных анимаций (spring/tween) поршней трубы и систем частиц.
- **Альтернативы**: `PyQt6`/`Tkinter` (сложнее делать игровые анимации и частицы 60 FPS), `Arcade` (тяжелее зависимости на Python 3.13).

### 2. Сдвиг высоты звука на -2 полутона для строя Си-бемоль (B♭)
- **Решение**:
  - Для написанных нот `M >= 62` можно использовать сэмпл `trumpet_{M-2}.ogg` (так как в папке есть сэмплы с 60 по 84, а `trumpet_60.ogg` как раз даёт концертное До = написанное Ре на трубе B♭!).
  - Для самых нижних написанных нот `M = 60` (написанное До1 $\rightarrow$ concert B♭3, MIDI 58) и `M = 61` (написанное До♯1/Ре♭1 $\rightarrow$ concert B3, MIDI 59), а также для единообразного тембра и управления длительностью (четверть / половинная / целая), загружать PCM-массив через `pygame.sndarray` + `numpy` и выполнять ресэмплинг с коэффициентом $2^{-2/12} \approx 0.8908987$ (или выбирать `M - 2` сэмпл там, где он есть, и ресэмплировать только для `M \in \{60, 61\}`). Кроме того, через `numpy`-огибающую (loop сустейна + плавный fade-out) можно формировать звучание под любую длительность (1, 2 или 4 доли).
- **Почему**: Даёт 100% точный унисон с живой трубой Си-бемоль во всём диапазоне от До1 до До3 без необходимости внешних утилит во время работы программы.

### 3. Захват микрофона и определение высоты тона: `sounddevice` + `numpy` (Автокорреляция / MPM)
- **Решение**: Использовать `sounddevice.InputStream` (частота дискретизации 44100 или 22050 Гц, размер окна ~2048 сэмплов) в фоновом потоке-колбэке и алгоритм нормализованной автокорреляции (McLeod Pitch Method / параболическая интерполяция пика на `numpy`) в диапазоне частот трубы (180–1100 Гц).
- **Почему**: Работает чисто на `numpy`, не требует устаревшего `aubio` (который плохо собирается на Python 3.13), даёт точность до 1–2 центов и задержку ~40–50 мс.
- **Логика транспозиции микрофона**:
  1. Измеренная частота $f$ переводится в концертный MIDI: $m_{\text{concert}} = 69 + 12 \log_2(f / 440)$.
  2. Написанная нота трубы B♭: $m_{\text{written}} = m_{\text{concert}} + 2$.
  3. Ближайшее целое `round(m_written)` — распознанная нота трубы, а разность `(m_written - target_midi) * 100` — отклонение в центах для индикатора тюнера.

### 4. Модель учебного курса и Spaced Repetition
- **Решение**:
  - Разбить курс на 6 уровней (глав):
    1. *Первые шаги*: `До1, Ре1, Ми1, Фа1, Соль1` (только натуральные, половинные и целые).
    2. *Вся первая октава*: добавляются `Ля1, Си1, До2` (+ четвертные ноты).
    3. *Любимые знаки трубача*: `Си♭1, Фа♯1, Ми♭1, До♯1` (знакомство с диезом, бемолем и бекаром из `assets/`).
    4. *Полная хроматика 1-й октавы*: `Ре♭1/До♯1`, `Ре♯1`, `Соль♯1/Ля♭1`, `Ля♯1`.
    5. *Вторая октава (вверх!)*: `Ре2, Ми♭2, Ми2, Фа2, Фа♯2, Соль2`.
    6. *Виртуоз (верхний регистр)*: `Ля♭2, Ля2, Си♭2, Си2, До3`.
  - Для каждой ноты хранить в профиле `NoteProgress`: `mastery` (0.0..1.0), `streak`, `last_practiced`, `error_count`, `unlocked`.
  - При генерации вопроса: с вероятностью 70% выбирается нота из текущих изучаемых (с весом, обратно пропорциональным `mastery`), а с вероятностью 30% — нота из уже освоенных ранее (с весом, растущим от давности `last_practiced` и `error_count`).

### 5. Архитектура модулей
```text
note_learn/
  __init__.py
  model.py        # Ноты (written MIDI 60..84), русские имена, ступени стана, аппликатуры (v1,v2,v3), длительности
  curriculum.py   # Уровни, генератор заданий (5 типов), Spaced Repetition, сохранение/загрузка прогресса JSON
  audio.py        # Загрузка assets/trumpet/*.ogg, сдвиг в строй Bb, синтез длительностей и метронома
  microphone.py   # Поток sounddevice, детектор частоты на numpy, транспозиция Bb (+2), трекер удержания длительности
  renderer.py     # Отрисовка нотного стана, скрипичного ключа, нот, PNG-знаков, анимированных помп, тюнера и частиц
  app.py          # Стейт-машина экранов (Меню/Карта уровней, Знакомство с нотой, Тренировка, Итоги раунда)
```

## Risks / Trade-offs

- **[Риск] Отсутствие микрофона или запрет доступа к микрофону в ОС** $\rightarrow$ Модуль `microphone.py` должен безопасно перехватывать ошибки инициализации `sounddevice`, автоматически предлагать режим «Без трубы» и позволять тренироваться без падения приложения.
- **[Риск] Шум комнаты или нестабильная атака звука у начинающего трубача** $\rightarrow$ Использовать порог громкости (RMS gate), сглаживание частоты по медианному окну из 3–5 фреймов и прощающее окно интонации (±45 центов), а также не сбрасывать прогресс удержания длительности мгновенно при кратком дрожании звука (<150 мс).
