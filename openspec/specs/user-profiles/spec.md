# user-profiles Specification

## Purpose
Позволяет нескольким людям заниматься на одном компьютере, храня прогресс обучения по курсу отдельно для каждого пользователя, и переключаться между ними без потери данных.

## Requirements

### Requirement: Несколько пользователей с отдельным прогрессом
Система SHALL поддерживать хранение нескольких пользователей одновременно, при этом прогресс обучения каждого пользователя (открытые этапы, освоенность нот, звёзды, XP, серия, режим «С трубой / Без трубы») SHALL храниться раздельно и не смешиваться с прогрессом других пользователей.

#### Scenario: Прогресс одного пользователя не влияет на другого
- **WHEN** пользователь A проходит задания и открывает новые ноты или этапы, после чего происходит переключение на пользователя B
- **THEN** у пользователя B отображаются только его собственные этапы, звёзды, серия и освоенность нот, без изменений, полученных пользователем A

#### Scenario: Возврат к пользователю сохраняет его прогресс
- **WHEN** пользователь A переключается на пользователя B, а затем обратно на A
- **THEN** весь прогресс пользователя A восстановлен без потерь

### Requirement: Добавление нового пользователя
Система SHALL позволять добавить нового пользователя с указанным именем; новый пользователь SHALL начинать обучение с чистого прогресса (первый этап, начальные ноты) независимо от прогресса других пользователей и SHALL автоматически становиться активным.

#### Scenario: Добавление пользователя с именем
- **WHEN** пользователь вводит непустое имя и подтверждает создание нового пользователя
- **THEN** в списке появляется новый пользователь, он становится активным, и открывается карта курса с чистым прогрессом первого этапа

#### Scenario: Пустое имя не создаёт пользователя
- **WHEN** пользователь пытается создать нового пользователя с пустым или состоящим из пробелов именем
- **THEN** новый пользователь не создаётся, а система сообщает о необходимости ввести имя

#### Scenario: Совпадающие имена не смешивают прогресс
- **WHEN** добавляется пользователь с именем, которое уже встречается в списке
- **THEN** создаётся отдельный пользователь со своим независимым прогрессом, а у обоих отображаются различимые записи в списке

### Requirement: Переключение активного пользователя
Система SHALL позволять переключить активного пользователя на любого из сохранённых; активный пользователь SHALL отображаться в интерфейсе, а его прогресс SHALL загружаться немедленно при переключении.

#### Scenario: Переключение на другого пользователя
- **WHEN** в списке пользователей выбирается другой пользователь и он становится активным
- **THEN** имя активного пользователя обновляется в верхней панели, а статистика и карта курса показывают прогресс выбранного пользователя

#### Scenario: Активный пользователь сохраняется между запусками
- **WHEN** пользователь выбирает активного пользователя, закрывает приложение и запускает его снова
- **THEN** при запуске активен тот же пользователь, что был выбран перед закрытием

### Requirement: Удаление пользователя
Система SHALL позволять удалить пользователя из списка после подтверждения; удаление SHALL удалять сохранённый прогресс именно этого пользователя и не затрагивать прогресс остальных. Система SHALL запрещать удаление последнего оставшегося пользователя.

#### Scenario: Удаление с подтверждением
- **WHEN** пользователь инициирует удаление пользователя и подтверждает действие
- **THEN** удалённый пользователь исчезает из списка вместе со своим сохранённым прогрессом, а прогресс остальных пользователей остаётся неизменным

#### Scenario: Отказ от удаления
- **WHEN** пользователь инициирует удаление, но отменяет подтверждение
- **THEN** пользователь и его прогресс остаются без изменений

#### Scenario: Удаление активного пользователя
- **WHEN** удаляется текущий активный пользователь, и в системе остаются другие пользователи
- **THEN** активным автоматически становится другой сохранённый пользователь, и приложение продолжает работу с его прогрессом

#### Scenario: Запрет удаления последнего пользователя
- **WHEN** в системе остался только один пользователь и предпринимается попытка его удалить
- **THEN** удаление не выполняется, и система сообщает, что должен остаться хотя бы один пользователь

### Requirement: Миграция одиночного профиля
При первом запуске с хранилищем пользователей система SHALL перенести существующий одиночный профиль `~/.note_learn_profile.json` в профиль пользователя по умолчанию без потери прогресса, не удаляя исходный файл.

#### Scenario: Перенос прогресса из старого файла
- **WHEN** приложение впервые запускается с хранилищем пользователей, а рядом существует `~/.note_learn_profile.json` с сохранённым прогрессом
- **THEN** создаётся профиль по умолчанию с этим прогрессом (звёзды, XP, серия, открытые этапы и освоенность нот совпадают), он становится активным, а исходный файл остаётся на диске

#### Scenario: Первый запуск без старого профиля
- **WHEN** приложение запускается впервые, и файла `~/.note_learn_profile.json` нет
- **THEN** создаётся один профиль по умолчанию с чистым прогрессом, который становится активным

### Requirement: Устойчивость к повреждённым данным профилей
Система SHALL не завершаться с ошибкой при повреждённом или нечитаемом файле хранилища профилей или отдельного профиля, а SHALL продолжать работу с доступными данными.

#### Scenario: Повреждённый файл хранилища
- **WHEN** индекс хранилища профилей оказывается нечитаемым или содержит некорректные данные
- **THEN** приложение запускается с одним профилем по умолчанию и не падает

#### Scenario: Повреждённый файл отдельного пользователя
- **WHEN** файл прогресса выбранного пользователя повреждён
- **THEN** этот пользователь открывается с чистым прогрессом, а остальные пользователи и их прогресс остаются доступными
